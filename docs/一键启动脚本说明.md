# 一键启动脚本说明

`start.bat` 让你**不打开 IDE** 就能拉起整个项目。
也可以**做成桌面图标**，双击即启动。

## 快速开始

**首次使用（三件事）：**

1. 复制 `.env.example` 为 `.env`，填入两个 API Key：

   ```
   DEEPSEEK_API_KEY=sk-xxxxxxxx
   DASHSCOPE_API_KEY=sk-xxxxxxxx
   ```

   > ⚠️ 这两个 Key 是**必需**的。Spring AI 在启动时就要构建 ChatClient，
   > Key 为空会直接抛 `OpenAI API key must be set` 导致启动失败，
   > 所以脚本不会提供"跳过继续"的选项。

2. 双击 `install-shortcuts.bat`，在桌面创建两个图标。

3. 双击桌面上的 **Start Mental Health AI**。

## 桌面快捷方式

运行 `install-shortcuts.bat` 后，桌面会出现：

| 图标 | 作用 |
|---|---|
| **Start Mental Health AI** | 启动后端 + 前端，启动完成后**自动打开浏览器** |
| **Stop Mental Health AI** | 停止后端 + 前端 |

**特点：**

- **保留命令行窗口**——能看到实时自检进度；窗口不会自动关闭，
  你可以随时回看启动报告
- 启动完成后自动打开 http://localhost:5173
- **关闭启动窗口不会停止服务**，窗口里会明确提示这一点

> 💡 **如果移动了项目文件夹**，重新运行一次 `install-shortcuts.bat` 即可刷新图标指向的路径。

> 💡 快捷方式实际是指向 `cmd.exe`，参数为
> `/c "set MH_KEEP_OPEN=1&& "<项目路径>\start.bat" [参数]"`。
> `MH_KEEP_OPEN=1` 让窗口在结束时保持打开。

## 命令

| 命令 | 作用 |
|---|---|
| `start.bat` | 启动全部（依赖自检 → 后端 → 前端） |
| `start.bat backend` | 只启动后端 |
| `start.bat frontend` | 只启动前端 |
| `start.bat check` | 只做环境自检，不启动任何服务 |
| `start.bat stop` | 停止后端与前端 |

**可用的环境变量：**

| 变量 | 作用 |
|---|---|
| `MH_KEEP_OPEN=1` | 结束后保持窗口打开（快捷方式自动设置） |
| `MH_NO_BROWSER=1` | 启动完成后不自动打开浏览器 |

## 脚本做了什么

```
[1/4] 检查依赖服务     MySQL 3306 / Redis 6379 / RabbitMQ 5672
                       ↓ 任一未就绪则中止，并给出启动命令
[2/4] 检查 API Key     DEEPSEEK_API_KEY / DASHSCOPE_API_KEY
                       ↓ 缺失则中止（这是硬依赖，不会有"跳过"）
[3/4] 启动后端         mvn spring-boot:run（后台运行）
                       ↓ 监测启动标志，失败时快速中止并指出原因
[4/4] 启动前端         npm run dev（后台运行）
                       ↓
                      自动打开浏览器 http://localhost:5173
```

**启动完成后：**

- 前端 http://localhost:5173
- 后端 http://localhost:1236
- 日志 `.run/logs/backend.log`、`.run/logs/frontend.log`

## 设计说明

**为什么用 `.env` 而不是系统环境变量**

项目本身从环境变量读取密钥（`application.yml` 里是 `${DEEPSEEK_API_KEY:}`）。
但用系统环境变量有两个问题：改一次要重启终端、换机器要重配。
脚本会**自动加载同目录的 `.env`**，把配置和项目放在一起，`.env` 已被 `.gitignore` 忽略。

**为什么日志重定向到文件**

后端和前端都在后台运行。如果某次启动失败，
进程一闪而过看不到原因，所以输出同时写入 `.run/logs/`。

**失败时为什么能快速中止**

脚本不盲目等满 180 秒。等待循环里会监测 Maven 的 `BUILD FAILURE`，
一旦出现就立即停止，并**从日志中提取真正的原因**（如缺少 API Key、
端口被占用、连不上 MySQL），而不是让你自己去 80 行 Maven 输出里翻。

**如何判断后端"真的"就绪**

脚本做了**双重判断**：

1. **优先匹配日志中的启动标志** `Started AiSpingbootApplication` ——
   这能证明应用**完整启动完成**，而不只是有进程占住了端口；
2. 兜底再探测 **1236 端口**是否 LISTENING。

每次启动前会**清空 `backend.log`**，否则上一次运行残留的标志会造成**误判成功**。

**为什么显式指定 JDK 17**

项目 `pom.xml` 声明 `<java.version>17</java.version>`，
而本机 `JAVA_HOME` 指向 JDK 21。脚本会在常见安装路径中探测 JDK 17 并显式使用，
避免因版本差异导致编译异常。**如果你机器上的 JDK 17 装在别处，
请在 `start.bat` 顶部的 `if exist` 清单里加上你的路径。**

**停止时为什么不动 MySQL / Redis / RabbitMQ**

它们是系统级服务，可能同时被其他项目使用，脚本只停自己启动的后端与前端。
停止方式是按**端口占用的进程**精确终止，并连带清理子进程（`taskkill /t`），
避免 `mvn` / `node` 的派生进程残留。

> 停止后可能仍能看到端口的 `TIME_WAIT` 记录，那是内核回收 TCP 连接的正常状态，
> 几秒到几十秒后自动消失。判断是否真的停了，看有没有 **LISTENING**。

**脚本内避免使用的命令**

- **不用 `timeout`**：在 stdin 被重定向时（如 `start.bat < nul`，或被其他脚本调用）
  会报 `Input redirection is not supported` 并使等待循环变成**空转**。
  统一改用 `ping -n N 127.0.0.1` 实现延时。
- **不用 `start /min cmd`**：新控制台会继承调用方的 stdin，
  **导致调用方进程被卡住不退出**。改用 `start /b` + `>log 2>&1 <nul` 完全脱离 stdio。

## 常见问题

**依赖服务未就绪**

```bat
net start mysql
net start RabbitMQ
```

Redis 用 Memurai（Windows 上的 Redis 替代），它注册为 Windows 服务，
用 `services.msc` 或 `net start Memurai` 启动。

**RabbitMQ 是强依赖**——它没启动，后端应用会直接启动失败。

**后端 180 秒还没起来**

首次运行 Maven 需要下载依赖，可能超时。看日志：

```powershell
Get-Content .run\logs\backend.log -Tail 50
```

依赖下载完之后，后续启动通常在几十秒内。

**改了 RabbitMQ 超时配置后启动报 `PRECONDITION_FAILED`**

队列参数（含 TTL）创建后不可修改。必须**按顺序**重建：

```powershell
# 1. 先停应用（否则运行中的应用会立即重新声明旧队列）
start.bat stop
# 2. 删队列
curl -u guest:guest -X DELETE http://localhost:15672/api/queues/%2F/crisis.timeout.high
curl -u guest:guest -X DELETE http://localhost:15672/api/queues/%2F/crisis.timeout.normal
curl -u guest:guest -X DELETE http://localhost:15672/api/queues/%2F/crisis.timeout.check
# 3. 再启动，队列会按新配置重建
start.bat
```

**端口被占用**

`start.bat stop` 会清理 1236 和 5173 端口上的进程。

```bat
REM 后端
cd ai-spingboot
mvn spring-boot:run

cd ai-vue
npm run dev
```
